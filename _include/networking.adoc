专属主机:: 与其他应用程序共享的主机不支持此代理。主机必须是专用主机。


VPC 和子网:: 创建 Console 代理时，需要指定其所在的 VPC 和子网。


VNet 和子网:: 创建 Console 代理时，需要指定其所在的 VNet 和子网。


与目标网络的连接:: Console 代理需要与您计划创建和管理系统的位置建立网络连接。例如，您计划在本地环境中创建 Cloud Volumes ONTAP 系统或存储系统的网络。


出站互联网接入:: 部署 Console 代理的网络位置必须具有出站 Internet 连接才能联系特定端点。


从 NetApp 控制台联系的端点:: 当您使用通过 SaaS 层提供的基于 Web 的 NetApp Console 时，它会与多个端点联系以完成数据管理任务。这包括为从 Console 部署 Console 代理而联系的端点。
+
--
link:reference-networking-saas-console.html["查看从 NetApp 控制台联系的端点列表"]。

--


Azure 区域:: 如果您使用 Cloud Volumes ONTAP，则应将控制台代理部署在与其管理的 Cloud Volumes ONTAP 系统相同的 Azure 区域中，或部署在 Cloud Volumes ONTAP 系统的 https://docs.microsoft.com/en-us/azure/availability-zones/cross-region-replication-azure#azure-cross-region-replication-pairings-for-all-geographies["Azure 区域对"^]中。此要求可确保在 Cloud Volumes ONTAP 与其关联的存储帐户之间使用 Azure 专用链接连接。
+
--
https://docs.netapp.com/us-en/storage-management-cloud-volumes-ontap/task-enabling-private-link.html["了解 Cloud Volumes ONTAP 如何使用 Azure 专用链接"^]

--


端口:: 除非您主动发起，或者将其用作将 AutoSupport 消息从 Cloud Volumes ONTAP 发送到 NetApp 支持的代理，否则不会有流入 Console 代理的流量。
+
--
* HTTP (80) 和 HTTPS (443) 提供对本地 UI 的访问，您可以在极少数情况下使用本地 UI。
* 只有在需要连接到主机进行故障排除时，才需要 SSH (22)。
* 如果在出站 Internet 连接不可用的子网中部署 Cloud Volumes ONTAP 系统，则需要通过端口 3128 进行入站连接。
+
如果 Cloud Volumes ONTAP 系统没有出站互联网连接来发送 AutoSupport 消息，Console 将自动配置这些系统使用 Console 代理附带的代理服务器。唯一的要求是确保 Console 代理的安全组允许通过端口 3128 进行入站连接。部署 Console 代理后，需要打开此端口。



--


代理服务器:: NetApp 支持显式和透明代理配置。如果使用的是透明代理，则只需提供代理服务器的证书即可。如果使用显式代理，则还需要 IP 地址和凭据。
+
--
* IP 地址
* 凭据
* HTTPS 证书


--


Azure 中的公用 IP 地址:: 如果要将公用 IP 地址与 Azure 中的 Console 代理 VM 一起使用，则 IP 地址必须使用基本 SKU，以确保 Console 使用此公用 IP 地址。
+
--
image:screenshot-azure-sku.png["在 Azure 中创建新 IP 地址的屏幕截图，可让您在 SKU 字段下方选择\"基本\"。"]

如果使用标准 SKU IP 地址，则 Console 会使用 Console 代理的_private_ IP 地址，而不是公共 IP 地址。如果用于访问 Console 的计算机无法访问该专用 IP 地址，则来自 Console 的操作将失败。

https://learn.microsoft.com/en-us/azure/virtual-network/ip-services/public-ip-addresses#sku["Azure 文档：公共 IP SKU"^]

--


启用 NTP:: 如果您计划使用 NetApp Data Classification 扫描公司数据源，则应在 Console 代理和 NetApp Data Classification 系统上启用网络时间协议 (NTP) 服务，以便在系统之间同步时间。 https://docs.netapp.com/us-en/data-services-data-classification/concept-cloud-compliance.html["详细了解 NetApp 数据分类"^]
