= 连接您的 LLM 并在 NetApp Console 本地部署中启用 NetApp Console 助手
:hardbreaks:
:allow-uri-read: 
:nofooter: 
:icons: font
:linkattrs: 
:imagesdir: ./media/


[role="lead"]
连接受支持的 LLM 端点，使受管理的自然语言存储指导和操作可供 NetApp Console 本地部署用户使用。


NOTE: 本文档以技术预览形式提供有关将 LLM 连接到 Console 助理以启用 AI 功能的文档。通过此预览产品，NetApp 保留在正式发布之前修改产品详情、内容和时间表的权利。

.必需的访问角色
超级管理员或组织管理员。link:reference-iam-predefined-roles.html["了解访问角色"]。

设置完成后，用户从控制面板打开 Console 助理并选择访问模式：

* 在*只读*模式下，助手回答问题并提供指导，而不进行任何更改。
* 在"读/写"模式下，助手可以对存储基础设施进行操作。它会在每次更改前显示详细信息以供审核和确认。对于异步操作（例如创建卷），它会创建一个作业，用户可以从助手检查该作业。


要连接您的 LLM，请选择提供程序路径，输入端点详细信息和 API 密钥，然后在 *Administration > AI Tools* 中选择一个模型。助手操作在您的存储策略和基于角色的访问控制范围内执行。



[[gather-what-you-need-before-you-connect-an-llm]]
== 在连接 LLM 之前，请先收集所需信息

准备提供商凭据和端点访问权限，以便 Console 助手可以在组织配置的治理边界内运行。

* 您的提供程序类型决定：OpenAI、OpenAI 兼容或 Anthropic，由版本和端点支持。
* 您选择的提供程序路径的有效 API 密钥。
* 提供程序路径的端点 URL。
* LLM 提供商帐户的用户名或 ID（如有需要）。
* 从 Console 本地部署到选定端点的网络访问。


link:reference-llm-supported-models.html["了解 NetApp Console 本地部署中受支持的 LLM 提供程序和模型"].



[[connect-an-llm-to-netapp-console-local-deployment]]
== 将 LLM 连接到 NetApp Console 本地部署

通过经过验证的提供程序配置启用助手功能，同时保留对端点凭据的管理控制。

.步骤
. 登录到 NetApp Console 本地部署。
. 选择 *Administration > AI Tools*。
. 选择菜单，然后选择 *Edit*。
. 在*提供程序类型*中，选择一个提供程序类型。
+
link:concept-llm-integration.html["了解 LLM 在 NetApp Console 本地部署中的集成"]。

. 如果提示输入提供程序端点，请输入所选提供程序路径的端点 URL。
. 在*用户名*字段中，输入您的用户名或 SSO ID（如果您的提供商路径需要）。
. 在 *API key* 字段中，粘贴您所选提供商路径中的 API 密钥。
. 从列表中选择一个模型。
. 查看配置，然后选择 *Save*。
+
在保存配置之前，请检查提供程序类型、端点 URL、API 密钥和所选模型。





[[verify-that-llm-integration-works]]
== 验证 LLM 集成是否有效

确认助理的可用性和审批行为，以便用户可以依靠配置的集成进行受管操作。

.步骤
. 在*只读*模式下打开*控制台助手*并运行基本查询。
. 在*读/写*模式下打开*控制台助手*，确认更改存储的操作需要用户确认后才能执行。
. 验证需要操作工作流的用户是否具有所需的基于角色的访问控制。


完成验证后，用户可以从仪表板打开 Console 助理，并以简单的语言描述任务。link:task-console-asst-use.html["了解如何使用 NetApp Console 助手"].



[[protect-credentials-and-monitor-llm-usage]]
== 保护凭据并监控 LLM 使用情况

保护 LLM 凭据并监控提供商活动，以减少未经授权使用集成并支持组织治理。

* 尽可能使用专用 API 密钥进行 Console 本地部署集成。
* 根据您的组织策略轮换 API 密钥。
* 根据组织的治理要求，监控提供商端 API 使用情况和警报。
